# 测量方法

所有结论都要能复现：写明时间段、测试机、轮数、方法。

## 延迟：用「复用连接」

经代理节点发 HTTP 请求时，**第一次请求**要建立到节点的连接（TCP + TLS/WS + 协议握手），耗时是真实往返的 2–4 倍。拿它当「延迟」会严重高估，尤其是远的节点（例：洛杉矶真实 ~160 ms，新建连接测出来 ~650 ms）。

正确做法：一条连接上连续请求 10–11 次，丢掉第一次，取中位数。

```sh
# 11 次请求复用同一条连接（经 socks5 代理），输出每次耗时（毫秒），去掉第一次后取中位数
args=""; for i in $(seq 11); do args="$args -o /dev/null http://www.gstatic.com/generate_204"; done
curl -s -x socks5h://127.0.0.1:7891 -w '%{time_total}\n' $args \
  | awk 'NR>1{printf "%.0f\n",$1*1000}' | sort -n | awk '{a[NR]=$1} END{print a[int((NR+1)/2)]" ms"}'
```

新建连接的耗时也值得记一列：它影响「打开网页的第一下」。

## 带宽：看单连接，多测几轮

- 单连接：下载 50 MB（香港测速文件，例如各机房提供的 100 MB 测试文件，用 Range 取前 50 MB）。
- 4 连接：4 × 15 MB 并发。
- **至少 3 轮取中位数**；同一条线单轮差异可达一倍。
- 在家庭网关上测，要避免测试流量被网关自己的透明代理再截一次（见 pitfalls）。

## 丢包与晚高峰

- 20:00–23:00 至少测一轮；记录中位数、最大值、失败次数。
- 专线段单独测（入口机 → 落地机 ping / mtr），和端到端结果对照，才能定位短板在哪一段。

## 批量测一组节点

`scripts/line-bench.sh`：在 Linux / OpenWrt 上起一个临时 mihomo，每个节点一个本地端口，逐个测：新建连接延迟（p50 / max / 失败数）、单连接和 4 连接带宽、复用连接延迟。`SKIP_DL=1` 只测延迟（用于家宽出口，别拿别人的家宽跑大流量）。

输出每行：`节点|新建p50|新建max|失败/20|单连接Mbps|4连接Mbps|复用p50|复用max`。

## 在外测

手机 4G / 5G 下用客户端自带的延迟测试 + 实际下载一个文件；分别测「回家」和「直连云入口」。
