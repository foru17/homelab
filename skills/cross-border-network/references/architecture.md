# 分层模型与参考拓扑

## 分层模型

```
[人在哪]        家 A / 家 B / 在外手机
   │  家里网关（OpenClash / mihomo）或手机客户端
[国内入口]      离家近的云机器（同省或邻省），7–10 ms
   │
[跨境段]        专线 ×2–3（云联网 CCN / IPLC / IEPL），互为备份  ← 唯一值得花钱的一段
   │
[香港落地 hub]  一台统一落地机：分流规则只维护一份
   │
[出口]          香港机房 IP / Cloudflare WARP / 各地家宽（只出不进）/ 美国机器
```

另有一条**不经香港**的旁路：电信家宽 → CN2 GIA → 洛杉矶小机器（美国前门），应用放在更便宜的美西机器上。

## 参考拓扑（已脱敏）

一套实际在跑的配置，数字是 2026-09 中午实测（复用连接延迟 / 单连接带宽，3 轮中位数）。

| 层 | 组成 | 关键数字 |
|---|---|---|
| 家 | 家 A（联通）、家 B（电信），各一台软路由网关 | — |
| 国内入口 | 广州的两台云机器（一台 BGP 白名单入口、一台固定 IP 中转） | 家 → 入口 7–8 ms |
| 跨境段 | 腾讯云联网 CCN（主力）、深港 IPLC（第二条）、深港 IEPL（即将退役） | 专线段 7.6 ms，晚高峰 0 丢包 |
| 香港落地 | 一台统一落地机 + 一台热备落地（10G 口） | 家 → 香港 19 ms；单连接 300–400 Mbps |
| 香港直连 | 一台 2000M 口的抢占式云主机，在外时直连用 | 单连接约 370 Mbps |
| 出口 | 香港机房 IP、WARP、香港 / 日本 / 新加坡家宽（只出不进）、美国 WARP | 家 → 东京 ≈ 83 ms |
| 美国 | 洛杉矶 CN2 GIA 1C2G（前门 + DERP + 中继），圣何塞两台便宜应用机 | 家 → 洛杉矶 ≈ 158 ms，0 丢包 |
| 组网 | Tailscale；香港、美国各有自建 DERP / peer relay | 美西两家上游互不通，经中继 312 → 13 ms |

月成本约 ¥700（其中即将退役的一条专线约 ¥250），相比 AI 订阅与 Token 开销是小头。

## 为什么多条专线落到同一台机器

- 出口 IP 一致：服务端看到的是同一个 IP，风控更稳定。
- 分流规则只在 hub 上维护一份；家里网关只负责「选哪条专线」。
- 调度器按实时延迟选线，「任一存活即可」，单线故障基本无感。
- hub 机器自己挂了怎么办：准备一台热备落地（可以是另一条专线的落地机），网关里把它放进同一个选择组。

## 家宽出口怎么接

- 家宽出口（任何你能合法使用的境外家庭宽带）**只出不进**：hub 能连它，它连不回 hub。
- 接入方式：tailnet 内由 hub 拨出，或 hysteria2 / SS-2022 等加密通道，一律强制鉴权。
- 掉线自动重连 + 推送告警；家宽 IP 会变，别把 IP 写死。

## 在外怎么用

- 首选「回家」：手机先连回家里网关，再按家里的规则出去，体验和在家一致。
- 回家的路多备几条：IPv6 直连、DDNS、CDN 边缘前置（阿里 ESA / 腾讯 EdgeOne）、经国内云机器中转（避开某些网络的 QoS）。
- 回不了家时，走自己的云入口进专线，或直连香港 / 美国机器。
