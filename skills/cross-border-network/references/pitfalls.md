# 踩过的坑

| 坑 | 现象 | 解决 |
|---|---|---|
| 用新建连接的请求时间当延迟 | 远端节点「延迟」高 3–4 倍，误判线路差 | 复用连接测（见 measurement.md） |
| 单轮测速下结论 | 同一条线两轮差一倍 | 至少 3 轮取中位数，晚高峰单独测 |
| 在 OpenClash 路由器上起临时 mihomo 测速 | 测试连接被 OpenClash 的 OUTPUT 规则再代理一次，数字失真 | 临时内核用 `nogroup`（gid 65534）运行；DNS 用真实解析而不是 fake-ip |
| OpenClash 截走 Tailscale 自身的 UDP | tailnet 发往中继只有发没有收 | 在 OpenClash 自定义防火墙规则里对 Tailscale 的 fwmark（`0x80000/0xff0000`）直接 RETURN |
| 老版本 Tailscale 不支持 peer relay | 强制走中继后整片断开 | 路由器上的 Tailscale 升到支持 peer relay 的版本，升级脚本带自检与自动回滚 |
| 某些云主机 virtio 网卡 MTU | 小包正常、大包黑洞，下载卡住 | 出口网卡 MTU 调低（如 1492）并验证 |
| 美西两家机房上游互不连通 | 两台机器互访绕回国内，300+ ms | 选第三台机器做中继 / 自建 DERP，降到十几毫秒 |
| 家宽无公网 IPv4（CGNAT） | 回家入口不可达 | 用 IPv6 直连 + DDNS，或经 CDN 边缘 / 云机器前置 |
| 入口机有白名单 | 换了家宽 IP 后突然全断 | 家宽 IP 变动时自动加白；备一条不依赖白名单的前置线路 |
| 专线落地多台、规则多份 | 改一处忘一处 | 所有专线落同一台 hub，规则只维护一份 |
| 面板暴露在公网 | 被扫描、爆破 | 只认 tailnet；公网 403 / 444 |
| 境外机器用国内 DNS | 解析到国内 CDN，访问变慢或被污染 | 境外服务器用 1.1.1.1 / 8.8.8.8 |
| 3x-ui 大版本升级 | 空 email 的客户端被丢弃 | 升级前给所有客户端补 email，先在隔离环境演练 |
| 按量计费没上限 | 账单意外飙升 | 先建预算告警和硬上限 |
